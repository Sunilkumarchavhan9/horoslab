              TRAINING SIGNAL / TRAJECTORY CONTRACT [ADDITIVE]
              A versioned training record may contain:
              ├── Task and environment IDs / versions
              ├── Input observation and relevant context
              ├── Model / policy checkpoint that produced the output
              ├── Action, response, tool calls or state prediction
              ├── Expected outcome, ground-truth label or preference
              ├── Verifier output and reward components, where applicable
              ├── Success / failure / termination reason
              ├── Data source, license, consent and provenance
              └── Runtime / token / compute cost, where measured

              Use only fields appropriate to the training method.
              Keep training, validation and held-out evaluation splits
              independently versioned and protected from leakage.

APPENDIX — ADDITIVE MODEL-BUILDING INTEGRATION
The original Horos architecture is retained in full. The additions above
connect it to a reproducible first-party model-development workflow.

Transferable design patterns integrated into existing Horos domains:
1. Reusable, versioned task and environment contracts.
2. Shared task harnesses for training, evaluation, simulation and replay.
3. Rollout / trajectory collection and inspection.
4. Explicit orchestration of training runs, resources, checkpoints and recovery.
5. Model, data, environment and experiment lineage in the model registry graph.
6. Versioned verifiers and reward definitions, with reward-gaming checks.
7. A promotion gate based on held-out evidence, not training reward alone.
8. A controlled loop from observed failures to eligible data, model updates,
   independent evaluation and safe deployment.

HOROS FIRST-PARTY MODEL OBJECTIVE
Build Horos Reality Decoder, Horos World Dynamics Model, Horos Code
Intelligence, Horos Voice Intelligence, and Horos Visual Generation.
Connect their development to Horos's existing Reality Intelligence,
Active Data Engine, Ground Truth Factory, compiler / kernel / runtime
optimization, deployment, observation, evidence, teaching and evolution.

Model lineage must distinguish training from scratch, continued
pretraining, fine-tuning / adapters, and distillation. External open-weight
models can be used as research baselines or initializers without
misrepresenting inherited weights as newly pretrained Horos weights.

PRINCIPLE
Use generalized training and environment orchestration patterns. Do not
make Horos dependent on any single external platform.

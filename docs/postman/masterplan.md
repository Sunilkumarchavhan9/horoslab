# 5. Core Product Loop

```text
1. Company connects sources.
2. memoryosTM ingests repo/docs/issues/agent chats.
3. memoryosTM extracts structured memory.
4. Knowledge Integrity Engine checks freshness, proof, contradictions, and risk.
5. Agent Experience Graph connects memory to tasks, agent runs, mistakes, outcomes, and skills.
6. User asks MemoryIgnition to prepare an agent.
7. memoryosTM compiles an inheritance package.
8. Agent Permission Runtime applies rules and allowed actions.
9. Inheritance Protocol delivers context to any target agent.
10. Agent works.
11. Agent Black Box records what happened.
12. Outcome is captured.
13. Human correction becomes future-agent instruction.
14. Mistake Immunity Engine creates prevention rules.
15. Skill Library stores approved repeatable patterns.
16. Agent Skill Installation Layer installs approved skills into the repo as agent-readable files.
17. Agent Skill Quality Engine prevents skill hell by checking trigger, structure, steering, pruning, proof, and context load.
18. Next agent inherits the lesson through installed repo skills, MCP/API/CLI, or an inheritance package.
```

## 6.19.2 Agent Skill Quality Engine

Purpose:

```text
Prevent skill hell by ensuring every agent skill is predictable, minimal, maintainable, proof-backed, and useful before it is installed into a codebase or exposed through MCP/API/SDK/CLI.
```

memoryosTM does not only generate skills. It evaluates, prunes, installs, versions, and governs them.

The Agent Skill Quality Engine checks every skill across four dimensions:

```text
trigger
structure
steering
pruning
```

### Trigger quality

Every skill must clearly define when it should be used.

Skill invocation types:

```text
user-invoked
model-invoked
router-invoked
workflow-invoked
```

Each skill must include:

```text
trigger context
when to use
when not to use
target agent type
supported task types
risk level
required memory scope
```

Rules:

```text
If the human explicitly chooses the skill, use user-invoked.
If the agent must discover the skill automatically, use model-invoked.
If many skills exist, use a router skill to select the right skill.
If a workflow always requires the skill, invoke it through a workflow blueprint.
```

### Structure quality

Every skill must be split into:

```text
steps
reference
context pointers
```

Rules:

```text
put the core procedure in SKILL.md
move long background material into reference files
keep SKILL.md minimal
use context pointers for branch-specific details
keep one source of truth for every rule
```

Recommended repo structure:

```text
.memoryos/skills/auth-system/SKILL.md
.memoryos/skills/auth-system/references/architecture.md
.memoryos/skills/auth-system/references/risky-files.json
.memoryos/skills/auth-system/references/required-tests.json
.memoryos/skills/auth-system/references/past-failures.md
.memoryos/skills/auth-system/references/proof.json
```

### Steering quality

Every skill should use strong leading words that guide agent behavior.

Examples:

```text
guardrail
proof
red-line
blast-radius
migration-safety
source-of-truth
replay
rollback
trace
```

Bad instruction:

```text
Be careful when changing auth.
```

Better instruction:

```text
Auth changes are red-line work. Before editing, identify blast radius, required tests, rollback path, and approval owner.
```

### Pruning quality

memoryosTM must remove skill sediment before installation.

Check for:

```text
duplicate instructions
stale rules
no-op lines
unclear wording
contradictory references
unused context
old decisions
overlapping skills
too much model-invoked context
```

Skill quality scores:

```text
trigger clarity score
context load score
structure score
steering score
pruning score
proof coverage score
freshness score
skill usefulness score
```

Skill approval gate:

```text
clear trigger
minimal SKILL.md
valid references
source proof attached
no duplicate rules
no stale instructions
required tests attached
approval owner defined if high risk
completion criteria included
```

Skill Hell Risk detection:

```text
too many model-invoked skills
multiple skills with the same trigger
skills that are never used
skills that cause wrong invocation
skills that increase context without improving outcomes
skills with repeated failures
skills without proof
```

When detected, memoryosTM suggests:

```text
merge skills
split skill
convert to user-invoked
convert to router-invoked
move content to reference
deprecate stale skill
rewrite trigger
add completion criteria
```

Core promise:

```text
memoryosTM does not just generate agent skills.
memoryosTM keeps agent skills clean, predictable, proven, installable, and safe.
```

# 14. First Real Production Path

Do not build temporary demo logic.

Build this first:

```text
1. User creates workspace.
2. User imports GitHub repo, docs, and agent chat.
3. memoryosTM extracts structured memories.
4. User opens MemoryIgnition.
5. User asks to prepare an agent.
6. memoryosTM generates inheritance package.
7. User copies package or sends via MCP/API.
8. AgentRun is created.
9. Agent Black Box records what happened.
10. User captures outcome.
11. Human correction creates FutureAgentInstruction.
12. Mistake Immunity Engine creates prevention rule.
13. Agent Skill Installation Layer writes approved skills into `.memoryos/`.
14. Agent Skill Quality Engine checks trigger, structure, steering, pruning, proof, and context load.
15. Next agent inherits the lesson through installed skills or live MemoryIgnition.
16. Replay proves the next agent avoids the mistake.
```

This is the real product loop.

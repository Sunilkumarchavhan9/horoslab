# HOROS First-Party Model Program: PROBE-1
## 08 — Technical Proposal & Architecture Specification

### 1. PROBE-1 System Architecture
PROBE-1 implements a **Dual-Frequency Flow-Matching Embodied Foundation Architecture (HOROS-DualFlow)**:

```
[Camera Streams (Head + Wrists)] ────► [Multi-View ViT Encoder (SigLIP-2)]
                                                        │
[Language Instruction] ──────────────► [Text Tokenizer] │
                                                        ▼
                                    [HOROS-Physical-LLM Trunk]
                                    (3.8B Sparse MoE: 1.1B active/token)
                                    - Operates at 10 Hz
                                    - Outputs: Latent Goal Token z_goal
                                                        │
                                                        ▼
[Tactile Sensors + IMU + Proprio] ──► [Sensor Fusion MLP-Mixer]
                                                        │
                                                        ▼
                                    [Continuous Flow-Matching Controller]
                                    (45M Parameter Lightweight DiT)
                                    - Conditional vector field: v_θ(x_t, t, z_goal, s_t)
                                    - Optimal Transport Flow Formulation
                                    - 3-step ODE Euler solver
                                    - Generates 32-step Action Chunk (0.32s)
                                    - Operates at 100 Hz
                                                        │
                                                        ▼
                                    [Independent Control Barrier Filter (CBF)]
                                    - Real-Time Quadratic Programming (QP)
                                    - Enforces: τ_min ≤ τ ≤ τ_max, d_collision ≥ 30mm
                                                        │
                                                        ▼
                                            [Actuator Motor Inverters]
```

### 2. Mathematical Formulation of the Flow Matching Controller
Let $\mathbf{a} \in \mathbb{R}^{H \times D}$ denote the action trajectory chunk of horizon $H=32$ across $D=29$ humanoid joints. Rather than training a stochastic diffusion process with multiple iterations, PROBE-1 adopts **Optimal Transport Flow Matching (OT-CFM)**:
$$\mathcal{L}_{\text{CFM}}(\theta) = \mathbb{E}_{t, p(\mathbf{a}_1), p(\mathbf{a}_0)} \left\| v_\theta(t, \mathbf{a}_t, \mathbf{c}) - (\mathbf{a}_1 - \mathbf{a}_0) \right\|^2$$
where $\mathbf{a}_t = t\mathbf{a}_1 + (1 - t)\mathbf{a}_0$ is the linear probability path between Gaussian noise $\mathbf{a}_0 \sim \mathcal{N}(\mathbf{0}, \mathbf{I})$ and ground-truth demonstration chunk $\mathbf{a}_1$, conditioned on context $\mathbf{c} = [\mathbf{z}_{\text{goal}}, \mathbf{s}_{\text{tactile}}, \mathbf{s}_{\text{proprio}}]$.
During inference, actions are generated by solving the ordinary differential equation (ODE):
$$\frac{d\mathbf{a}}{dt} = v_\theta(t, \mathbf{a}_t, \mathbf{c})$$
using a 3-step mid-point Euler integrator, executing in $7.2$ ms on NVIDIA Jetson Thor.

### 3. Safety Verification Boundary
Before sending commanded joint targets $\mathbf{a}^*$ to the low-level hardware inverters, the commands pass through a deterministic safety filter solving the following convex optimization problem at 500 Hz:
$$\mathbf{u}^* = \arg\min_{\mathbf{u}} \frac{1}{2} \| \mathbf{u} - \mathbf{a}^* \|^2$$
$$\text{subject to } \dot{B}(\mathbf{x}, \mathbf{u}) + \alpha(B(\mathbf{x})) \ge 0 \quad (\text{Control Barrier Function for Collision Avoidance})$$
$$\boldsymbol{\tau}_{\min} \le \mathbf{J}^T(\mathbf{q}) \mathbf{u} \le \boldsymbol{\tau}_{\max} \quad (\text{Joint Torque Safety Limit})$$

This guarantees that physical hardware safety is mathematically independent of neural network failure, drift, or OOD hallucination.
